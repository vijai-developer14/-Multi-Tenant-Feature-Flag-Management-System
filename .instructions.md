# Copilot Instructions for Feature Flag Management System

## Project Overview
This is a MERN stack application (MongoDB, Express, React, Node.js) for managing feature flags in a multi-tenant SaaS environment. The system has three user roles (Super Admin, Org Admin, End User) with separate frontend applications.

## Architecture & Structure

### Backend Architecture
- **Pattern**: MVC (Model-View-Controller)
- **Port**: 5000
- **Framework**: Express.js
- **Database**: MongoDB with Mongoose ODM

**Folder Structure:**
```
back-end/
├── config/db.js              # Database connection
├── controller/               # Business logic
│   ├── authController.js     # Auth verification
│   └── orgController.js      # Organization CRUD
├── middleware/
│   └── checkAuth.js          # JWT verification middleware
├── model/                    # Mongoose schemas
│   ├── adminUsers.js         # User schema
│   ├── featureFlag.js        # Feature flag schema
│   └── organization.js       # Organization schema
├── routes/
│   └── orgRoutes.js          # API route definitions
└── server.js                 # Express app initialization
```

### Frontend Architecture
- **Build Tool**: Vite
- **Ports**: 
  - Super Admin: 5173
  - Org Admin: 5174
  - End User: 5175

**Three React Applications:**
1. `super-admin-front-end` - FULLY IMPLEMENTED - Organization management interface
2. `org-admin-front-end` - SCAFFOLD ONLY - Feature flag management (to be implemented)
3. `end-user-front-end` - SCAFFOLD ONLY - Feature flag checking (to be implemented)

## Coding Standards & Conventions

### Backend (Node.js/Express)

#### Naming Conventions
- **Files**: kebab-case (e.g., `org-routes.js` or `orgRoutes.js` - currently mixed)
- **Functions**: camelCase (e.g., `getOrganizations()`, `createUser()`)
- **Variables**: camelCase (e.g., `orgData`, `userId`)
- **Constants**: UPPER_SNAKE_CASE (e.g., `MAX_RETRIES`, `DEFAULT_TIMEOUT`)
- **Collections**: snake_case or plural (e.g., `organizations`, `users`)

#### Code Organization
- Keep controllers focused on single responsibility
- Use middleware for cross-cutting concerns (auth, logging, error handling)
- Group related routes together
- Use descriptive variable names over single letters (except loop counters)

#### Error Handling
```javascript
// Good: Specific error responses
try {
  // logic
  res.status(200).json(result);
} catch (error) {
  res.status(500).json({ message: "Specific error message", error: error.message });
}

// Avoid: Generic responses
res.status(500).json(error);
```

#### API Response Format
```javascript
// Standard success response
{
  "message": "Operation successful",
  "data": { /* actual data */ }
}

// Standard error response
{
  "message": "Human-readable error message",
  "error": "error details"
}
```

### Frontend (React/Vite)

#### Naming Conventions
- **Components**: PascalCase (e.g., `LoginForm.jsx`, `AdminPanel.jsx`)
- **Hooks/Functions**: camelCase (e.g., `useAuth()`, `fetchOrganizations()`)
- **Variables/State**: camelCase (e.g., `orgName`, `isLoading`)
- **CSS Classes**: kebab-case (e.g., `admin-panel`, `login-form`)

#### Code Organization
- One component per file
- Keep components focused and reusable
- Extract logic into custom hooks or utility functions
- Group related state together with useState

#### State Management Pattern
```javascript
// Use useState with clear, descriptive names
const [organizations, setOrganizations] = useState([]);
const [isLoading, setIsLoading] = useState(false);
const [error, setError] = useState(null);

// Use useEffect for side effects (API calls)
useEffect(() => {
  const fetchData = async () => {
    setIsLoading(true);
    try {
      const response = await fetch(API_URL);
      const data = await response.json();
      setOrganizations(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setIsLoading(false);
    }
  };
  
  fetchData();
}, []); // Run once on mount
```

#### API Integration Pattern
```javascript
// Centralized API base URL
const API_BASE = "http://localhost:5000/api";

// Fetch options for authenticated requests
const options = { 
  credentials: "include", // Include cookies (for JWT)
  headers: { "Content-Type": "application/json" }
};

// Use in components
const response = await fetch(`${API_BASE}/endpoint`, {
  method: "POST",
  ...options,
  body: JSON.stringify(data)
});
```

## Common Tasks & How to Implement

### Adding a New API Endpoint

1. **Define route** in `back-end/routes/orgRoutes.js`:
   ```javascript
   orgRoutes.post("/features", verifyToken, createFeature);
   ```

2. **Implement controller** in `back-end/controller/`:
   ```javascript
   const createFeature = async (req, res) => {
     try {
       const { key, isEnabled, orgId } = req.body;
       // Validate input
       if (!key || !orgId) {
         return res.status(400).json({ message: "Missing required fields" });
       }
       // Create in DB
       const feature = new featureFlagSchema({ key, isEnabled, orgId });
       const result = await feature.save();
       res.status(201).json({ message: "Feature created", data: result });
     } catch (error) {
       res.status(500).json({ message: "Creation failed", error: error.message });
     }
   };
   ```

3. **Add model if needed** in `back-end/model/`:
   - Define schema with Mongoose
   - Export model: `module.exports = mongoose.model("name", schema)`

4. **Update frontend** to consume endpoint:
   ```javascript
   const createFeature = async (featureData) => {
     const response = await fetch(`${API_BASE}/features`, {
       method: "POST",
       ...options,
       body: JSON.stringify(featureData)
     });
     return response.json();
   };
   ```

### Fixing Common Issues

#### CORS Errors
- Check that backend CORS includes the frontend port
- Verify credentials: "include" is set on frontend fetch calls
- Ensure backend has `credentials: true` in CORS config

#### JWT Token Not Being Sent
- Verify `credentials: "include"` in all authenticated fetch calls
- Check that token is in HttpOnly cookie (not localStorage)
- Verify middleware is checking `req.cookies.token`

#### Database Connection Issues
- Check MongoDB service is running
- Verify `MONGO_URI` in .env is correct
- Check connection string format for your MongoDB setup

#### Hot Reload Not Working
- Backend: Ensure `nodemon` is installed and running with `npm run dev`
- Frontend: Verify Vite is running and no port conflicts
- Check file save triggers reload (may need to wait a moment)

## Important Notes & Warnings

### Security Considerations
- ⚠️ **Passwords are stored in plain text** - Implement bcrypt hashing before production
- ⚠️ **Super admin credentials in .env** - Use proper secrets management for production
- ⚠️ **Secure flag set to false** - Change to `true` for HTTPS in production
- ⚠️ **No rate limiting** - Add rate limiting middleware for production

### Known Technical Debt
- Inconsistent error response formats (some return just error, some with message)
- No input validation on most endpoints
- No logging system implemented
- Frontend apps not connected to API (scaffold only)
- Mixed naming conventions in some files (orgRoutes vs org_routes)

### Before Going to Production
1. Add input validation using express-validator or joi
2. Implement password hashing (bcrypt)
3. Add comprehensive error handling and logging
4. Implement rate limiting (express-rate-limit)
5. Add database indexes for performance
6. Implement comprehensive testing (Jest, Supertest for backend; Vitest for frontend)
7. Add API documentation (Swagger/OpenAPI)
8. Implement CI/CD pipeline
9. Add security headers (helmet.js)
10. Set up monitoring and alerting
